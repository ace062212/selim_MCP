# 04. 도구 켜기/끄기 정책

도구는 관리자와 사용자 둘 다 켜고 끌 수 있다. 두 설정이 부딪힐 때의 규칙을 정리한다.

## 확정된 규칙

| # | 규칙 | 결정 |
|---|---|---|
| 1 | 관리자 설정과 사용자 설정이 부딪히면? | **관리자가 이긴다.** 관리자가 끈 도구는 사용자가 켜도 쓸 수 없다 |
| 2 | 새 도구가 추가되면 사용자에게는? | **기본 켜짐.** 사용자가 직접 끈 경우에만 꺼진다 |
| 3 | 설정을 바꿀 때마다 인증번호를 받나? | **아니요.** 한 번 인증하면 30분 세션 동안 자유롭게 변경 |

## 최종 사용 가능 여부

```
사용 가능 = 관리자가 켬(tools.enabled) AND 사용자가 끄지 않음(user_tools.enabled, 없으면 true)
```

| 관리자 | 사용자 | 결과 | 사용자 화면 표시 |
|---|---|---|---|
| 켬 | (설정 없음) | ✅ 사용 | 스위치 켜짐 |
| 켬 | 켬 | ✅ 사용 | 스위치 켜짐 |
| 켬 | 끔 | ❌ | 스위치 꺼짐 |
| 끔 | 무엇이든 | ❌ | 스위치 비활성 + "관리자가 비활성화함" |

DB에서는 뷰 `v_user_tools.effective_enabled`로 바로 조회한다.

관리자가 끈 도구를 다시 켜면, 사용자가 예전에 직접 꺼둔 설정은 그대로 유지된다 (사용자 설정은 지우지 않음).

## 변경이 클라이언트에 반영되는 방식

- MCP 클라이언트는 접속할 때 `tools/list`로 도구 목록을 받는다.
- 서버는 이 응답에 **그 사용자가 쓸 수 있는 도구만** 담는다.
- 관리자나 사용자가 설정을 바꾸면 서버가 `notifications/tools/list_changed`를 보내서 클라이언트가 목록을 다시 받게 한다.
  - 클라이언트가 이 알림을 지원하지 않으면 다음 접속 때 반영된다.
- 목록에서 빠진 도구를 직접 호출해도 서버가 `403`으로 막는다 (목록만 믿지 않음).

## 도구 추가·삭제 흐름

도구 자체는 코드로 관리한다. 관리자 화면에서는 운영 설정만 바꾼다.

| 작업 | 누가 | 방법 |
|---|---|---|
| 새 도구 추가 | 개발자 | 서버 코드에 도구 추가 후 배포 → 시작 시 `tools`에 자동 등록 (관리자 켜짐, 사용자 기본 켜짐) |
| 도구 삭제 | 개발자 | 코드에서 제거 후 배포 → `tools.retired_at` 기록, 목록에서 사라짐 |
| 켜기/끄기 | 관리자 | 관리자 화면 > MCP 도구 |
| 설명 수정 | 관리자 | `tools.description_override` (Claude가 도구를 고를 때 읽는 문장) |
| 개인 켜기/끄기 | 사용자 | 사용자 화면 > 도구 설정 (예정) |

## 나중에 검토할 것

- **부서별 권한**: 특정 도구를 특정 부서만 쓰게 하기 → `tool_permissions(tool_id, dept)` 테이블 추가.
- **게이트웨이 방식**: 외부 MCP 서버를 관리자 화면에서 등록해 묶어서 제공 → `mcp_servers` 테이블 추가.
